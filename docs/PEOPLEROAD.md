## 1. 왜 바꾸나 — 국장이 말한 매체 사업의 구조

국장 이력: 2003년 하반기 인턴으로 언론 시작 → 2004년부터 신문·잡지 여러 곳 → 2014년 TTL뉴스
창간(여행 기사 비중 70%, 여행 키워드는 조선일보보다 높이 노출) → 작년 퍼블릭뉴스와 합병,
지금은 편집국장(월급). 퍼블릭뉴스는 32번째 통신사 인가. 여행 담당 출입은 "누가 뺏으려 해도
못 뺏는" 본인 네트워크. [녹취 00:08~04:15, 22:18, 42:02]

대표 이력(국장에게 설명한 것): 전자공학 → 영화 기술·마케팅(예고편·DVD·디지털 전환) →
창업 → 정부 부처(여성가족부·고용노동부·문체부) 마케팅 → 트위터·구글·에어비앤비·오픈AI와
협업 → 여행업 → 3년간 콘텐츠 자동 발행 시스템 개발(홈페이지·티스토리·워드프레스·네이버
블로그·카페·인스타·페북·스레드·X·숏폼, 특허) → 오픈AI와 계약, 현재 80개 업체 자동화.

### 1-1. 매체만으로는 돈이 안 되지만, 매체가 있어야 큰 사업이 된다 [녹취]

- "매체로 돈 벌겠다고 하면 말릴 거예요. 그게 아니라 시너지라면 권유드리는 거죠." (47:27)
  여행 매체 창업은 권하지 않지만 피플레이는 대행사 + 상품 보유라 구조가 달라서 권한다.
- **대회 주관·후원** — 매경 골프엑스포 모델. 매체가 이름을 빌려주고 참가비 수익을 셰어한다.
  대행사가 아무리 영업해도 브릿지스톤·타이틀리스트는 매체가 있어야 온다. (36:20~38:20)
- **공공사업** — 관광청·관광공사·문체부. "사기업이라 못 건드리는 영역을 매체가 집어넣어
  줄 수 있다." (44:20) 정부 기관과 일하려면 네이버 노출이 돼야 한다. (01:10:47)
- **협찬 구조** — 기사 한 건에 돈 받는 것이 아니다. 광고비·협찬 명목으로 받고 기사를 써 준다.
  "돈 받고 기사 써준다? 이러면 문제가 돼요. 우리가 기사를 써 주기 때문에 고마워서 해 주는
  거야. 그래서 협찬이거든요." (33:21~34:24)
- **여행 매체 8곳** — 연 200~300만원씩 주면 월 2~3건씩 알아서 써 주고, 사고 기사도 덮어 준다.
  배너는 오히려 싫어한다(다른 중소 매체가 달려든다). (38:57~41:16)
- **대행사와 언론사는 붙어 있다** — 대행사가 예산을 태워 언론사를 관리하고, 언론사는 그
  클라이언트를 챙긴다. 피플레이는 대행사이므로 자체 매체가 곧 이 고리다. (34:47~35:58)

## 2. 새 판 — 구조

```
피플로드 (문화 전문 매체 · 네이버 카테고리 '문화')
├─ 여행  /travel/                       ← 와플트립 지면을 그대로 잇는다
│   ├─ 지역면 10곳  /guam/ /saipan/ /hawaii/ /vietnam/ /kota/ /laos/ /jeju/ /japan/ /thailand/ /taiwan/
│   ├─ 부문 7개     /biz/ /issue/ /policy/ /feature/ /world/ /people/ /data/
│   ├─ 도시면       /city/tokyo/ … (기사 8건 이상인 도시만)
│   └─ 기사        /<region>/<id8>-<slug>/
├─ 연예  /ent/                          ← 신설. 지역 없음
│   ├─ 영화 /ent/movie/ · 드라마·방송 /ent/drama/ · 음악·공연 /ent/music/ · 인물 /ent/star/
│   ├─ 스타의 여행 /ent/startrip/        ← 교차 부문. 위에 '피플레이와 함께한 스타' 표
│   └─ 기사        /ent/<id8>-<slug>/
├─ RSS  /rss.xml (전체) · /ent/rss.xml (연예) · /<region>/rss.xml (지역)
└─ 매체 쪽  /about/ /ethics/ /contact/ /privacy/ /youth/ /subscribe/ /search/
```

- **상단 메뉴**: `여행 ▸ 여행BIZ … 통계·리포트 │ 연예 ▸ 영화 드라마·방송 음악·공연 인물 스타의 여행 │ 구독 · 제보·문의 · 검색`
- **홈**: 톱·사이드·데이터 띠·헤드라인은 두 채널 공통(연예 기사도 우리 글이면 톱에 올 수 있다).
  아래 블록은 여행 부문 → 연예 부문 순. **기사가 없는 연예 부문 블록은 그리지 않는다.**
- **연예 기사의 사진**: 지역 사진 자동 배정이 돌지 않는다. 직접 찍고 동의 받은 사진만 프론트매터 `photo` 로.
- **서명**: 여행은 `피플로드 ○○ 데스크`, 연예는 `피플로드 문화부`. 실명 기자가 정해지면 그 이름.
- **검색 색인·사이트맵·llms.txt·RSS**: 연예 기사 포함. 브레드크럼은 `피플로드 › 연예 › 영화 › 기사`.

### 2-1. 연예 부문의 재료 — 어디서 가져오나 [결정 — 추천안 채택]

- 소속사·배급사·제작사·방송사 **보도자료와 공식 발표**
- **현장**: 시사회·쇼케이스·제작발표회·공연 — 우리가 가서 찍는다
- **국장 소스**: 행사 사진 2~3장 + 메모 → 당일 발행 (`--field` 양식)
- 남의 연예인 사진 **금지**(저작권 + 초상권). AI 인물(유나 등)은 연예 기사에 못 쓴다.
- 열애설·사생활·루머 **금지** — 편집원칙 3번에 명시했다.
- 첫 3개월은 관계 만들기. 국장 네트워크로 현장 출입. 화보·PPL 수익은 등록 후, 그것도 파생 채널에서.
- **수집 파이프라인(보도자료 RSS 자동 수집)은 아직 없다.** 편집실에서 사람이 쓴다. 공식 RSS 를
  붙일 때는 `sources.yaml` 에 channel 항목을 더하는 작업이 따로 필요하다.

### 2-2. 스타의 여행 · 피플레이와 함께한 스타 [결정]

사장님 지시: "플레이를 통해 다녀온 연예인들도 같이 넣어두면 좋을 것 같아."

- 자리: `/ent/startrip/` 맨 위 표 "피플레이와 함께한 스타" + 그 아래 스타의 여행 기사.
- 자료: `data/star_trips.yaml`. **지금 비어 있다.** 저장소 어디에도 명단이 없었고(Kim·waffletrip
  두 저장소 전수 검색 [실측 09-25]), 클로드는 지어내지 않는다. 사장님이 채운다.
- 항목: 활동명·소속/작품·소속사·여행지·장소·시기·함께한 플레이·목적·**consent**·동의 근거·기사 경로·사진.

- 표에는 운영사와의 관계를 밝히는 문장이 함께 붙는다(편집원칙 4번). 등록 심사 관점에서도
  "우리 상품 홍보"로 읽히지 않게 **상품 링크 없이 사실만** 적는다.
